## 1. Objective & Invariants
This specification defines the runtime contract for the **Redeem-Before-Act Gate** across the AIOS dispatch fabric.
- **Invariant I-2 (Atomic Single-Use Redeem Gate)**:
  A consequential tool (`pentest.*`, `fs.write`, `exec.*`, etc.) is structurally unreachable unless an active, unredeemed capability grant exists, and the PEP atomically commits a `pep.capability.redeem` audit row before handing control to the tool dispatcher.

## 2. API Specifications

### 2.1 Python `audit_client.grant_redeem()`
Located in `code/aiosh-mcp/aiosh_mcp/audit_client.py`:

```python
def grant_redeem(
    conn: sqlite3.Connection,
    grant_id: str,
    actor: str,
    actor_id: str,
    tool: str,
    command: str,
    args: dict[str, Any] | None = None,
    target: str | None = None,
) -> dict[str, Any]:
    """Atomically redeem a capability token prior to tool execution.

    Returns:
        {"ok": True, "grant": dict, "audit_row": AuditRow}
    or:
        {"ok": False, "reason": str}
    """
```

#### Pre-conditions:
1. `grant_id` must exist in `pep_grants` and `revoked_at` must be `NULL`.
2. `expires_at` must be greater than current UTC timestamp.
3. Tool must match grant's allowed `scope.tools` glob pattern.
4. Target (if provided) must match `scope.paths` or `scope.networks`.
5. If `single_use == 1`, `redeemed_at` must be `NULL`.

#### Execution Semantics:
1. Execute atomic conditional SQL write:
   ```sql
   UPDATE pep_grants SET redeemed_at = ?
   WHERE grant_id = ? AND redeemed_at IS NULL AND revoked_at IS NULL AND expires_at > ?
   ```
2. If `cur.rowcount == 0`:
   - Inspect existing record to determine specific failure reason (`"already redeemed at ..."`, `"expired"`, `"revoked"`, or `"not found"`).
   - Return `{"ok": False, "reason": reason}` without emitting a redeem row.
3. If `cur.rowcount == 1`:
   - Insert `pep.capability.redeem` audit row into `audit_ring` via `write_audit_row()`.
   - Wrap in `try...except`: if `write_audit_row()` fails, execute rollback `UPDATE pep_grants SET redeemed_at = NULL WHERE grant_id = ?` to maintain fail-closed consistency.
   - Return `{"ok": True, "grant": updated_grant, "audit_row": row}`.

## 3. Failure Envelopes & Audit Effects
- When redemption fails, the tool callback is never invoked.
- An explicit audit row with `outcome: "refused"` and `outcome_detail: "grant <id> already redeemed at <ts>"` is committed.
- When redemption succeeds, the `pep.capability.redeem` audit row is committed immediately, followed by the tool execution, which commits a subsequent result row upon completion.
