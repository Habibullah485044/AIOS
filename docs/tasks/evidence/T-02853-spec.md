## 1. Scope & System Invariant I-3

This specification formalizes **Component 3: Chain Anchoring & Completeness Checkpoints** of the Proof of Restraint architecture (ADR-0037, `PLAN.md` §Layer 2).

> **Invariant I-3 (External Anchor Immutability)**:
> Chain heads must be periodically anchored outside `audit.db`. Verification of restraint requires valid anchor signatures covering the query window. Any modified or truncated chain MUST fail verification against external signed anchors.

## 2. Cryptographic Anchor Schema

### 2.1 The Anchor Record (`AnchorRecord`)
Anchors are serialized as single-line JSON records appended to `$AIOSH_HOME/anchors/anchors.jsonl` (or an explicit path passed via configuration):

```json
{
  "schema_version": 1,
  "seq": 105,
  "head_hash": "c1a4e231b40286438072bc5df89032ad8e2cf5e1435790a88b56f9e9e1c31204",
  "timestamp": "2026-10-07T05:30:00Z",
  "pubkey": "d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a",
  "signature": "e5564300d984...<128 hex chars = 64 bytes Ed25519 signature>..."
}
```

### 2.2 Canonical Signed Payload
To guarantee cross-substrate determinism between Python, TypeScript, and Rust, the signed payload is computed by hashing the canonical JSON representation of the core triplet:

$$\text{payload} = \text{canonicalJson}\left(\{\text{"head\_hash"}: H, \text{"seq"}: S, \text{"timestamp"}: T\}\right)$$

The signature is generated over the UTF-8 bytes of this canonical JSON string using Ed25519 (RFC 8032):

$$\text{sig} = \text{Sign}_{\text{priv}}(\text{canonicalJson}(\dots))$$

## 4. Key Separation & Security Posture

1. **Storage Isolation**:
   - `audit.db` stores ZERO private keys. The SQLite schema contains NO key columns.
   - The private key is loaded from an external file (`$AIOSH_HOME/anchors/anchor_signer.key`), an environment variable `AIOSH_ANCHOR_KEY`, or an external secure service.
2. **Permissions**:
   - Key file must have file permissions `0600` (POSIX) or single-owner restricted DACL (Windows).
3. **Immutability of Anchors**:
   - `anchors.jsonl` is append-only.
   - Any truncation of `anchors.jsonl` is detected if audit clients or auditors cross-reference against external backup anchors or remote log servers.

## 5. Verification Invariants & Edge Cases

| Condition | Verification Result | Error Code |
|---|---|---|
| All anchors valid & matching rows | `True` | `None` |
| Corrupt signature on anchor | `False` | `SIGNATURE_INVALID` |
| Chain ends at seq 50, anchor seq is 100 | `False` | `TRUNCATION_DETECTED` |
| Row 100 hash != anchor seq 100 head_hash | `False` | `FORK_DETECTED` |
| Empty chain with non-empty anchors | `False` | `TRUNCATION_DETECTED` |
| Non-contiguous / gap sequence | Handled by internal WAL verify | `GAP_DETECTED` |
