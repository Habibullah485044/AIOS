## 1. Scope & System Invariant I-4

This specification formalizes **Component 4: Restraint Proof Generator** of the Proof of Restraint system (ADR-0037, `PLAN.md` §Layer 2, Invariant I-4).

> **Invariant I-4 (Zero-Trust Standalone Verifier)**:
> The proof generator must emit a self-contained cryptographic package (`restraint_proof.json`) that enables any external auditor with public keys to mathematically verify negative attestation (non-use) without having access to the live `audit.db` or database credentials.

## 3. Function Signatures & API Contract

### 3.1 Python (`aiosh_mcp/restraint.py`)
```python
def generate_restraint_proof(
    conn: sqlite3.Connection,
    grant_id: str,
    window_start: str,
    window_end: str,
    anchors_path: str | Path | None = None,
) -> dict[str, Any]:
    """
    Generates a self-contained RestraintProofPackage for grant_id across [window_start, window_end].
    
    Returns:
      {
        "ok": True,
        "proof": dict (RestraintProofPackage),
      }
    
    Error conditions:
      - GRANT_NOT_FOUND: grant does not exist in pep_grants.
      - GRANT_REDEEMED: grant was redeemed (contains redeemed_at or redeem audit row).
      - NO_COVERING_ANCHORS: cannot find valid start/end anchors covering window.
      - WINDOW_INVALID: window_start > window_end.
    """
```

### 3.2 CLI Interface (`aiosh prove restraint`)
```bash
aiosh prove restraint --grant <token> --start <iso> --end <iso> --out <file.json>
```

## 4. Operational Invariants & Audit Trace

Every invocation of `aiosh prove restraint` or `aios.restraint.prove` writes an audit row to `audit_ring`:
- `tool`: `"aios.restraint.prove"`
- `command`: `"prove restraint --grant <id>"`
- `args`: `{"grant_id": ..., "window_start": ..., "window_end": ...}`
- `outcome`: `"ok"` if `PROVABLY_RESTRAINED`, `"refused"` if grant was redeemed or unanchored.
