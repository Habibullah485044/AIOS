## 2. Tool Contract — `aios.compliance` ⟦AIOS⟧

Single tool, action-dispatch (mirrors the existing `aios.task` style; keeps `tools/list` stable — see D1).

```
aios.compliance(
    action: "list" | "show" | "register" | "status" | "assess" | "check-pep" | "init",
    id: str | None = None,             # show / register / status
    framework: str | None = None,      # list filter / assess
    status: str | None = None,         # list filter / status (next status)
    control_id: str | None = None,     # register
    target_type: str | None = None,    # register
    target_ref: str | None = None,     # register
    threat_ids: list[str] | None = None,   # register
    mitigation_summary: str | None = None, # register
    tags: list[str] | None = None,     # register
    reason: str | None = None,         # status transition reason
    gate_id: str | None = None,        # check-pep
    grant_id: str | None = None        # PEP capability grant (write actions)
) -> dict
```

### Per-action semantics

| action | Kind | Inputs required | Effect |
|---|---|---|---|
| `list` | read | `framework?`, `status?` (parse via `ComplianceFramework::parse_framework` / `ComplianceStatus::parse_status` vocabularies) | none |
| `show` | read | `id` | none |
| `register` | **write** (grant) | `id`, `control_id`, `framework`, `target_type`, `target_ref`, `status`, `mitigation_summary?`, `threat_ids?`, `tags?` | appends/inserts mapping entry; `DUPLICATE_ID` if `id` exists |
| `status` | **write** (grant) | `id`, `status` (next), `reason?` | `update_status` with state machine check |
| `assess` | read | `framework?` | none (report) |
| `check-pep` | read | `gate_id` | none |
| `init` | **write** (grant) | — | creates the store with the canonical baseline if absent; no-op error `STORE_EXISTS` if present |

Invalid `action` ⇒ error `PARAM_INVALID` (fail-closed, still audited).

## 3. Outputs (happy path)

Envelope matches the server-wide convention (research A4) — top-level `ok`, plus action payload, plus audit metadata injected by `_recorded_call`:

```json
{
  "ok": true,
  "action": "list",
  "count": 2,
  "mappings": [ { "id": "MAP-0001", "control_id": "AC-2", "framework": "nist_sp_800_53_rev5",
                  "target_type": "pep_gate", "target_ref": "gate.fs.write",
                  "threat_ids": ["T-0012"], "status": "compliant",
                  "mitigation_summary": "PEP gate enforces scoped grants",
                  "tags": ["access-control"], "created_at": "...", "updated_at": "..." } ],
  "audit_id": 123,
  "classifier_policy_revision": "rev-..."
}
```

- `assess` returns `{"ok": true, "action": "assess", "framework": ...|null, "report": {"total", "by_status": {...}, "by_framework": {...}, "entries": [...]}, "audit_id", ...}` — semantics identical to `ComplianceService::assess_framework`.
- `check-pep` returns `{"ok": true, "action": "check-pep", "gate_id", "covered": bool, "uncovered_required": [...]}` — semantics identical to `verify_pep_coverage` / `uncovered_pep_gates`.
- `show`/`register`/`status`/`init` return the affected entry (or `{"initialized": true}`) in the same envelope.

## 4. Failure Path (error cases)

Errors are data, never silent (ADR-0035 §F-2); every failure still produces exactly one audit row:

```json
{ "ok": false, "action": "show", "error": "COMPLIANCE_ERR_INVALID_ID: Mapping ID ...",
  "audit_id": 124 }
```

| Condition | `error` code | HTTP-equiv | CLI exit parity |
|---|---|---|---|
| Bad/missing arg, unknown action, unparsable enum | `PARAM_INVALID` | 400 | 2 |
| `id` fails identifier rules | `COMPLIANCE_ERR_INVALID_ID` | 400 | 2 |
| control id / title invalid | `COMPLIANCE_ERR_INVALID_TITLE` | 400 | 2 |
| Any bounds violation (§6) | `COMPLIANCE_ERR_BOUNDS_EXCEEDED` | 400 | 2 |
| Control characters in text | `COMPLIANCE_ERR_CONTROL_CHARS` | 400 | 2 |
| `register` with existing `id` | `COMPLIANCE_ERR_DUPLICATE_ID` | 409 | 2 |
| Illegal status transition | `COMPLIANCE_ERR_INVALID_STATUS_TRANSITION` | 409 | 2 |
| Empty `target_ref` | `COMPLIANCE_ERR_MISSING_SUBSTRATE_REF` | 400 | 2 |
| Mapping not found | `NOT_FOUND` ⟦AIOS⟧ | 404 | 2 |
| Store path invalid (non-`.json`, traversal) | `COMPLIANCESVC_ERR_PATH_TRAVERSAL` | 400 | 2 |
| Store unreadable/corrupt JSON | `STORE_UNAVAILABLE` ⟦AIOS⟧ | 500 | 3 |
| `init` on existing store | `STORE_EXISTS` ⟦AIOS⟧ | 409 | 2 |
| PEP refusal (missing/invalid grant on write) | gate envelope (existing) | 403 | — |

## 5. Persistence Effects

- **Store**: `docs/compliance_map.json` (default; overridable via `AIOSH_COMPLIANCE_MAP_PATH` ⟦AIOS⟧ env for tests). Path validation identical to `ComplianceService::validate_path`: must end `.json`, no traversal.
- **Capacity**: max `MAX_COMPLIANCE_ENTRIES_CAPACITY = 1024` entries; exceeding ⇒ `COMPLIANCE_ERR_BOUNDS_EXCEEDED`.
- **Canonical file form** ⟦AIOS⟧: UTF-8 (no BOM), LF, 2-space indent, non-ASCII unescaped, **object key order preserved from the loaded document** (writers MUST round-trip key order; never re-sort), exactly one trailing newline. Writes are atomic: serialize to `<path>.tmp` then `os.replace`. This matches `serde_json::to_string_pretty` output for the same key order (byte-stable cross-substrate).
- **Read-only actions never touch the store file** (mtime unchanged).

## 6. Validation Parity (normative source: `compliance_data_model.rs`)

Bounds (must be enforced identically in Python): `MAX_COMPLIANCE_ID_LEN=64`, `MAX_COMPLIANCE_TITLE_LEN=128`, `MAX_COMPLIANCE_DESC_LEN=2048`, `MAX_COMPLIANCE_NOTES_LEN=2048`, `MAX_THREAT_IDS_COUNT=16`, `MAX_TAGS_COUNT=16`, `MAX_COMPLIANCE_ENTRIES_CAPACITY=1024`. `status=compliant` requires non-empty `mitigation_summary`. Status machine `can_transition_to` is authoritative; unknown transitions ⇒ `COMPLIANCE_ERR_INVALID_STATUS_TRANSITION`. Framework aliases match `parse_framework` (`nist|nist_800_53`, `soc2|soc_2`, `iso|iso27001`, `cis|cis_v8`, `hipaa`, `pci|pci_dss`).

## 7. Audit Effects (every call, no exceptions)

- Exactly **one** audit row per `aios.compliance` call via `_recorded_call`: `tool="aios.compliance"`, `command="compliance <action>"`, `args` = validated params (never raw unvalidated input), `grant_token` = `grant_id` on write actions.
- Gate refusal ⇒ the gate's refusal row is the one row (no result row).
- Tool errors (post-gate) ⇒ one `outcome="error"` row with `outcome_detail` = the error code.
- No fail-open path exists in this surface: validation happens before persistence; persistence is atomic; audit emission is unconditional.

## 8. Gating Matrix

| action | `require_grant` | Notes |
|---|---|---|
| `list`, `show`, `assess`, `check-pep` | false | read-only |
| `register`, `status`, `init` | true | state-changing; `grant_id` must be a live capability whose scope covers `aios.compliance` |

## 9. Decision Log (resolving T-02893 D1..D8)

| # | Decision | Rationale |
|---|---|---|
| D1 | Single action-dispatch tool `aios.compliance` | matches `aios.task` precedent; bounded registry growth (A7); per-action gating handled internally |
| D2 | Rust service remains the CLI-side authority; the MCP surface implements the **contract** natively in Python (no subprocess, no second store) | sub-second tool latency; avoids `aiosh` binary dependency on MCP hosts |
| D3 | Canonical file form §5 (key-order-preserving round-trip) | byte-stable across Rust/Python writers without re-sorting serde output |
| D4 | Errors as envelope data (`ok:false` + code), not MCP `isError` exceptions | server-wide convention (A4); clients already parse envelopes |
| D5 | Tool annotations: conservative (`readOnlyHint=false, destructiveHint=false, idempotentHint=false, openWorldHint=false`) with per-action kind documented in the description | a union tool cannot honestly claim read-only; upstream annotations exist but do not model per-action semantics |
| D6 | No `outputSchema` yet | cross-cutting adoption belongs to a dedicated task; envelope keys are documented here instead |
| D7 | Integration must replace brittle tool-count smoke assertions with schema/annotation invariants | T-02887 finding (A7) |
| D8 | Bounds/error-code parity is binding (§6) | cross-substrate invariant (chain-wide rule) |

## 10. Non-Goals

No HTTP/REST API (ADR-0035 §D-2: MCP only). No `remove`/`delete` verb (not in the CLI surface). No direct `compliance_map.json` editing through other tools. No new frameworks beyond the closed enum of six.
