## 1. Scope & Objective

The automated test suite provides deterministic verification of Compliance Mapping across both production substrates. It asserts data model invariants, status transition rules, boundary limits, precedence ladder resolution, atomic file replacement, PEP gating, and ADR-0037 Proof-of-Restraint (Invariant I-2).

## 2. Test Vectors Specification (`AUTOCOMPLIANCE1`..`AUTOCOMPLIANCE10`)

### `AUTOCOMPLIANCE1`: Full Compliance Lifecycle & Status Transitions
- **Objective**: Verify allowed transitions across `not_assessed`, `in_progress`, `compliant`, `non_compliant`, and `not_applicable`.
- **Constraint**: Transition to `compliant` **must** fail closed if `summary` or `reason` is empty or missing.
- **Expected Result**: Transition succeeds only when accompanied by valid justification.

### `AUTOCOMPLIANCE2`: Duplicate Control & Collision Rejection
- **Objective**: Assert unique primary key invariant for `mapping_id`.
- **Input**: Attempt to register an entry whose `id` matches an existing control in the store.
- **Expected Result**: Fail closed with `COMPLIANCESVC_ERR_DUPLICATE_ID`. The store remains completely unchanged (atomic rollback).

### `AUTOCOMPLIANCE3`: Identifier, Text & Array Bounds Validation
- **Objective**: Enforce strict length boundaries and character hygiene.
- **Bounds Tested**:
  - `mapping_id`: $\le 64$ characters, matching `^[A-Za-z0-9_.:-]+$`.
  - `title`: $\le 256$ bytes, no control characters (`ord < 32`, `ord == 127`).
  - `summary`: $\le 4096$ bytes.
  - `threat_ids`: $\le 32$ entries.
- **Expected Result**: Any violation triggers `COMPLIANCE_ERR_PARAM_INVALID` / validation error.

### `AUTOCOMPLIANCE4`: 4-Level Precedence Ladder Resolution
- **Objective**: Test deterministic store resolution across all 4 levels:
  1. Level 1: Explicit argument (`--path`).
  2. Level 2: Environment variable (`AIOSH_COMPLIANCE_MAP_PATH`).
  3. Level 3: Configuration file (`--config` > `AIOSH_COMPLIANCE_CONFIG` > `docs/compliance_config.json`).
  4. Level 4: Built-in default (`docs/compliance_map.json`).
- **Expected Result**: Level $N$ overrides Level $N+1$. `source` map accurately identifies the origin of each parameter.

### `AUTOCOMPLIANCE5`: CWE-15 / CWE-22 Hygiene Predicate Defense
- **Objective**: Prevent path traversal and environment injection attacks.
- **Inputs**: `../escape.json`, `dir/\x00null.json`, strings $> 1024$ characters.
- **Expected Result**: Invalid env strings are tagged `env_invalid` and rejected, falling back safely to lower tiers without panicking.

### `AUTOCOMPLIANCE6`: Pre-Parse File Size Bounds & CWE-400 DoS Defense
- **Objective**: Prevent memory exhaustion via oversized config files or stores.
- **Bounds**:
  - Config file $> 64$ KiB (`MAX_CONFIG_FILE_BYTES`): fails with `COMPLIANCECONF_ERR_FILE_SIZE`.
  - Store file $> 16$ MiB (`MAX_MAX_STORE_FILE_BYTES`): fails with store size error.
- **Expected Result**: Evaluated before full JSON decoding.

### `AUTOCOMPLIANCE7`: Audit Immutability & Audit Logging Guarantee
- **Objective**: Guarantee all mutating compliance operations generate an immutable audit row.
- **Invariant**: `audit_all_mutations` cannot be set to `false`. Any config specifying `false` is clamped to `true`.
- **Expected Result**: Every store update commits a corresponding event to `audit_ring`.

### `AUTOCOMPLIANCE8`: Proof of Restraint & PEP Gating (Invariant I-2)
- **Objective**: Verify that state-changing compliance actions cannot execute without redeeming a single-use capability token.
- **Checks**:
  - Unauthenticated / ungranted mutation attempts return `PEP_DENIED` or fail closed.
  - Valid granted mutations execute and mark the capability token as redeemed.
  - Replay attempts using an already-redeemed token fail closed.

### `AUTOCOMPLIANCE9`: Assessment Scoring & Statistics Consistency
- **Objective**: Verify mathematical correctness of compliance coverage reports.
- **Calculations Tested**:
  - `total_controls = compliant + non_compliant + in_progress + not_applicable + not_assessed`.
  - `compliance_pct = (compliant / (total_controls - not_applicable)) * 100.0`.
  - Handling of zero denominator ($total - not\_applicable = 0 \to 100\%$).
- **Expected Result**: Reports return exact float/integer calculations across all framework filters.

### `AUTOCOMPLIANCE10`: Multi-Threaded Concurrency Safety & Atomic Replace
- **Objective**: Prevent file corruption and resource leaks under concurrent read/write stress.
- **Harness**: 8 worker threads performing concurrent additions, status updates, and reads against an isolated temporary store.
- **Expected Result**: Store maintains valid JSON syntax, zero lost updates, and zero lingering `.tmp.*` files on disk.
