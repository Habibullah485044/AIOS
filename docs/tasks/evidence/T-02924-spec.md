## 1. Scope & Non-Goals

**In scope**: Declarative governance and enforcement policies over Compliance Mapping operations:
- Control mapping registration evaluation (valid framework, required threat linkage, size limits).
- Status transition gating (especially transitions to `Compliant` requiring mitigations/reasons).
- System compliance assessment thresholds (minimum compliant percentage verification).
- Policy modes (`Enforcing`, `Permissive`, `Disabled`) and verdicts (`Permit`, `PermitWithWarning`, `Deny`).
- Atomic persistence with bounded file sizes (≤ 64 KiB) and path hygiene.
- Audit row emission and Proof-of-Restraint (PoR) Invariant I-2 compliance.

**Non-goals**:
- Does not modify existing underlying storage schema of `ComplianceCatalogSnapshot`.
- Does not bypass existing PEP capability token redemption gates on state-changing actions.
- Does not introduce network dependencies or unverified dynamic scripting.

## 3. Normative Contract

### 3.1 Policy Modes
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum CompliancePolicyMode {
    /// Invariant violations fail-closed returning Deny.
    Enforcing,
    /// Violations emit audit warning telemetry but return PermitWithWarning.
    Permissive,
    /// Policy evaluation passes unconditionally returning Permit.
    Disabled,
}
```

### 3.2 Policy Verdicts
```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(tag = "verdict", rename_all = "snake_case")]
pub enum CompliancePolicyVerdict {
    Permit,
    PermitWithWarning { warning: String },
    Deny { reason: String, code: String },
}
```

### 3.3 Security Policy Schema
```rust
pub const MAX_COMPLIANCE_SECURITY_POLICY_BYTES: u64 = 65_536; // 64 KiB

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ComplianceSecurityPolicy {
    pub version: String,
    pub mode: CompliancePolicyMode,
    pub require_threat_linkage: bool,
    pub require_mitigation_on_compliant: bool,
    pub permitted_frameworks: Vec<ComplianceFramework>,
    pub min_compliant_percentage: f64,
    pub max_catalog_mappings: usize,
    pub allow_canonical_override: bool,
}
```
**Defaults**:
- `version`: `"1.0.0"`
- `mode`: `CompliancePolicyMode::Enforcing`
- `require_threat_linkage`: `true`
- `require_mitigation_on_compliant`: `true`
- `permitted_frameworks`: `vec![]` (empty = all standard frameworks allowed)
- `min_compliant_percentage`: `80.0`
- `max_catalog_mappings`: `1024`
- `allow_canonical_override`: `false`

### 3.4 Evaluation Rules (Invariants COMPLIANCEPOL1..COMPLIANCEPOL7)
1. **`COMPLIANCEPOL1` (Version Conformance)**: `version` must start with `"1."` and be non-empty.
2. **`COMPLIANCEPOL2` (Mode Gating)**:
   - If `mode == Disabled`: returns `Permit` unconditionally.
   - If `mode == Enforcing`: any rule failure returns `Deny { reason, code }`.
   - If `mode == Permissive`: any rule failure returns `PermitWithWarning { warning }`.
3. **`COMPLIANCEPOL3` (Evidence & Mitigation Requirement)**:
   - When `require_mitigation_on_compliant` is true, transitioning to `ComplianceStatus::Compliant` requires `mitigation_summary` or `reason` with at least 3 characters. Otherwise fails with `COMPLIANCEPOL_ERR_MITIGATION_REQUIRED`.
4. **`COMPLIANCEPOL4` (Permitted Frameworks)**:
   - If `permitted_frameworks` is non-empty, registering a control whose framework is not in the list fails with `COMPLIANCEPOL_ERR_FRAMEWORK_PROHIBITED`.
5. **`COMPLIANCEPOL5` (Strict Threat Linkage)**:
   - When `require_threat_linkage` is true, entries with `threat_ids.is_empty()` fail with `COMPLIANCEPOL_ERR_THREAT_REQUIRED`.
6. **`COMPLIANCEPOL6` (Assessment Threshold)**:
   - Evaluating an assessment where `percentage < min_compliant_percentage` fails with `COMPLIANCEPOL_ERR_THRESHOLD_UNMET`.
7. **`COMPLIANCEPOL7` (Persistence & File Bounds)**:
   - File size must not exceed `MAX_COMPLIANCE_SECURITY_POLICY_BYTES` (64 KiB). Symlinks rejected. Atomic persistence via temporary file rename.

## 4. Error Code Family (`COMPLIANCEPOL_ERR_*`)

| Code | Trigger |
|---|---|
| `COMPLIANCEPOL_ERR_VALIDATION` | Malformed policy configuration (version invalid, out of bounds percentage or capacity). |
| `COMPLIANCEPOL_ERR_DENIED` | Generic fail-closed rejection under policy. |
| `COMPLIANCEPOL_ERR_THREAT_REQUIRED` | Entry lacks required threat links under strict linkage policy. |
| `COMPLIANCEPOL_ERR_MITIGATION_REQUIRED` | Attempt to mark control compliant without mandatory mitigation/reason. |
| `COMPLIANCEPOL_ERR_FRAMEWORK_PROHIBITED` | Framework not in permitted frameworks list. |
| `COMPLIANCEPOL_ERR_THRESHOLD_UNMET` | Assessment compliance score below policy threshold. |
| `COMPLIANCEPOL_ERR_CAPACITY_EXCEEDED` | Catalog mappings count exceeds policy maximum. |
| `COMPLIANCEPOL_ERR_OVERRIDE_FORBIDDEN` | Canonical override attempted without explicit policy permission. |
| `COMPLIANCEPOL_ERR_IO` | Filesystem reading, writing, or permission failure. |
| `COMPLIANCEPOL_ERR_PARSE` | Serialization / deserialization syntax error. |

## 5. Audit Row & Proof-of-Restraint Effects
- Any state-changing invocation (e.g. updating compliance security policy, or performing state transitions governed by policy) must emit an immutable audit row to `audit_ring` with:
  - `subsystem`: `"compliance_policy"`
  - `action`: `"policy_evaluate"` | `"policy_update"`
  - `actor`: caller identity
  - `verdict`: verdict string
  - `reason`: failure code or audit detail
- In accordance with Proof-of-Restraint Invariant I-2, policy configuration writes require prior redemption of capability token `cap:compliance:admin`.
