## 1. Specification Overview
The MCP/API surface specification defines the complete interaction contract for external models and automated agents invoking incident runbooks and RustSec scanning tools over Model Context Protocol:

1. **`aios_runbook` Tool**:
   - Actions: `list`, `show`, `init`, `start`, `step`, `confirm`, `status`, `abort`.
   - Reuses `RunbookCatalogSnapshot` and `RunbookExecutionSession` from `incident_runbook_service.py`.
   - Mutating actions (`start`, `step`, `confirm`, `abort`) require PEP capability grant (`cap:runbook:execute`).
   - Read-only actions (`list`, `show`, `status`) operate without grants.

2. **`aios_scan` Tool**:
   - Actions: `net` (port scanning), `files` (IOC regex discovery), `web` (HTTP endpoint probing).
   - Reuses validation rules and bounds clamping matching the Rust substrate in `sec_tools.rs`.
   - Requires respective capability grants (`cap:net:scan`, `cap:fs:search`, `cap:web:probe`).

3. **Invariants Enforced**:
   - `IRMCP-INV1`: Authoritative gate dispatch with audit logging on every tool invocation.
   - `IRMCP-INV2`: PEP capability token verification.
   - `IRMCP-INV3`: Input sanitization and bounds enforcement.
   - `IRMCP-INV4`: Standard result envelope (`{ok, action, data, error, audit_id}`).
   - `IRMCP-INV5`: Thread-safe session management.
