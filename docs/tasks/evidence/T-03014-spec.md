## 1. Scope & Objective

The automated test battery provides comprehensive, deterministic end-to-end verification of the Incident Response Runbooks and RustSec scanning subsystem across both the Rust Core substrate and the Python FastMCP substrate. It verifies the complete execution state machine, high-risk operator confirmation gates, parameter validation and interpolation, forensic scanning filters, 4-level configuration resolution, dynamic concurrency capping, and Proof-of-Restraint (Invariant I-2) compliance.

## 2. Test Vectors Specification (`AUTORUNBOOK1`..`AUTORUNBOOK10`)

### `AUTORUNBOOK1`: Catalog Snapshot & Spec Integrity
- **Objective**: Verify baseline catalog snapshots (`RB-IR-MALWARE-01`, `RB-IR-ACCESS-01`), step sequence counts, phase invariants, and schema completeness.
- **Constraints**:
  - `RB-IR-MALWARE-01`: Containment phase, severity High, 3 automated steps.
  - `RB-IR-ACCESS-01`: Eradication phase, severity Critical, Step 2 flagged as `requires_confirmation = true`.
- **Expected Result**: Deserialization produces valid snapshots with exact step definitions and parameters.

### `AUTORUNBOOK2`: Session State Machine Transitions
- **Objective**: Assert valid lifecycle progressions (`Pending` -> `Running` -> `AwaitingConfirmation` -> `Completed`).
- **Constraints**: Cannot advance from terminal states (`Completed`, `Failed`, `Aborted`). Advancing beyond the final step completes the session.
- **Expected Result**: Invalid transitions fail closed with `RUNBOOK_ERR_INVALID_TRANSITION`.

### `AUTORUNBOOK3`: High-Risk Operator Confirmation Gate
- **Objective**: Prove that high-risk or confirmation-required steps cannot advance unattended.
- **Constraints**: If `step_def.requires_confirmation` or `step_def.is_high_risk()` is true and `operator_confirmed` is false, state must transition to `AwaitingConfirmation`.
- **Expected Result**: Step execution is blocked until explicit confirmation token/call is submitted.

### `AUTORUNBOOK4`: Parameter Extraction & Injection Defense
- **Objective**: Validate template placeholder rendering `{{parameter_name}}` and reject parameter injection.
- **Constraints**:
  - Max parameters per session $\le 32$.
  - Max parameter value length $\le 256$ bytes.
  - Parameter values must pass alphanumeric/safe-character whitelist regex `^[a-zA-Z0-9_\-\.:/\\~@]+$`.
- **Expected Result**: Unsafe parameters fail closed with `RUNBOOK_ERR_INVALID_PARAM_VALUE`.

### `AUTORUNBOOK5`: Forensic File Pattern Scanning (ripgrep-grade)
- **Objective**: Assert high-performance regex searching for indicators of compromise (IOCs).
- **Constraints**:
  - Recursion depth bound $\le 32$.
  - File size cap $\le 16$ MiB.
  - Max matches capped at 1000.
  - Traversal paths (`..`) and control characters rejected with `SEC_ERR_INVALID_TARGET`.
- **Expected Result**: Discovers targeted synthetic markers cleanly with line numbers and truncated match strings.

### `AUTORUNBOOK6`: Network & Web Port Scanning Hygiene
- **Objective**: Verify TCP port scanning and HTTP web endpoint fuzzing.
- **Constraints**:
  - Target host must pass whitelist regex.
  - Ports clamped within `[1, 65535]`.
  - Max web wordlist entries clamped at 1000.
- **Expected Result**: Open ports and discovered endpoints are reported with accurate millisecond timings and zero socket/FD leaks.

### `AUTORUNBOOK7`: 4-Level Configuration Ladder Resolution
- **Objective**: Test deterministic precedence:
  1. Level 1: Explicit argument overrides.
  2. Level 2: Environment variables (`AIOSH_RUNBOOK_*`).
  3. Level 3: Configuration file (`docs/runbook_config.json`).
  4. Level 4: Built-in defaults.
- **Expected Result**: Level $N$ overrides Level $N+1$; per-field `sources` provenance accurately reflects origin (`argument`, `env`, `file`, `default`).

### `AUTORUNBOOK8`: Dynamic Concurrency & Active Session Eviction
- **Objective**: Enforce memory bounds under heavy session creation stress.
- **Constraints**: `max_active_sessions` clamped within `[1, 10000]`.
- **Expected Result**: When total sessions reach `max_active_sessions`, oldest sessions are evicted from memory store cleanly without memory leakage.

### `AUTORUNBOOK9`: Proof-of-Restraint Authorization & Audit Trail (Invariant I-2)
- **Objective**: Verify that consequential runbook containment and scanning actions require valid PEP grants and record an immutable audit row.
- **Constraints**: Consequential actions (`start`, `step`, `confirm`, `abort`, `scan.net`, `scan.files`, `scan.web`) commit an audit row with `audit_id > 0`.
- **Expected Result**: Every operation writes exactly one row to SQLite `audit_ring`.

### `AUTORUNBOOK10`: Standardized Fail-Closed Result Envelopes
- **Objective**: Verify panic-free error handling and standardized result envelopes.
- **Constraints**: Corrupted JSON, oversized files ($> 64$ KiB), and missing sessions return structured envelopes with `ok: false`, standardized `error_code`, and fallback safe defaults.
- **Expected Result**: Zero daemon crashes or unhandled panics under malformed payloads.
