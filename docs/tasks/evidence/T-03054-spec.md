## 1. Scope & Subsystem Architecture

The Incident Response Runbooks Recovery & Validation subsystem protects the integrity of incident runbook specifications, persistent state, active session tracking, and configuration ladders. It provides:
1. Non-destructive health and schema validation (`validate_state_path` / `validate_config_path`).
2. Atomic repairs with crash consistency.
3. Timestamped quarantine isolation (`.quarantine.<timestamp>`) ensuring corrupted files are preserved for post-incident forensics.
4. Bounded quarantine file rotation (`MAX_QUARANTINE_FILES = 10`).
5. Canonical baseline re-initialization and snapshot rollback.
6. Unified FastMCP integration under `aios_runbook` (`action="recovery_check"`, `"recovery_repair"`, `"recovery_snapshot"`).

## 4. Invariants

- **IRREC-INV1 (Non-Destructive Validation)**: Inspecting state files must never mutate files, alter active sessions, or rotate backups.
- **IRREC-INV2 (Atomic File Replacement)**: State files must be written to temporary siblings (`.tmp.<pid>.<ts>`) and renamed via `rename(2)` with `sync_all` to guarantee crash-safe atomicity.
- **IRREC-INV3 (Mandatory Quarantine on Corruption)**: Any corrupted file must be copied to `.quarantine.<timestamp>` before re-initialization or overwriting.
- **IRREC-INV4 (Bounded Quarantine Footprint)**: Older quarantine files exceeding `MAX_QUARANTINE_FILES = 10` are pruned automatically.
- **IRREC-INV5 (Proof-of-Restraint Accountability)**: All repair, quarantine, and snapshot operations are executed via `_recorded_mcp_call`, writing immutable audit rows with assigned `audit_id`.
